# StartCard.ai

От краткой бизнес-задачи к понятному студенческому проекту и ручному выбору команды.

**Команда:** bears — Байбусин Кайдар, Бейбитов Санжар, Ескендиров Масуд.
**Трек:** 07 — Образование. **Кейс:** AI Sana StartCard: от бизнес-задач к решению.

Название трека и кейса взято из предварительных материалов команды. Полного официального ТЗ в репозитории нет. AI-подбор и ранжирование команд остаются расширением идеи, а не реализованной функцией этой версии.

## Что решает продукт

Бизнесу сложно получить подходящий результат, если задача описана одной фразой. Студентам нужны понятные данные, ограничения и критерии приёмки перед откликом. StartCard помогает уточнить постановку, проверить карточку и собрать предложения команд. Экономия времени и качество подбора пока не измерялись.

Основной путь: **черновик → вопросы → ответы → редактируемая карточка → рейтинг готовности → публикация → каталог → отклик → ручное решение бизнеса**.

В интерфейсе используется название **StartCard.ai**. Это один проект, с одним сервером для UI и API.

## Что работает

| Этап | Реализация и статус |
|---|---|
| Черновик и уточнения | Ввод задачи, шесть вопросов; запрос к серверу. Без ключа работает явно обозначенный резервный режим |
| Карточка | Сервер формирует поля из ответов; перед публикацией человек редактирует и подтверждает текст |
| Рейтинг готовности | Правила заполненности семи полей, 0–100; пересчёт в UI и на сервере при публикации |
| Каталог | Карточки загружаются из общего backend; поиск, фильтры по теме и готовности |
| Отклик | Команда отправляет название, идею, план, срок, контакт и необязательную ссылку |
| Ручной выбор | Бизнес принимает или отклоняет отклик; можно принять несколько команд |
| Обновление страницы | Карточки, отклики и решения повторно загружаются с сервера |

Рейтинг показывает заполненность описания по правилам. Он не является оценкой качества решения моделью, проверкой достоверности сведений или AI-рейтингом команды.

## Быстрый запуск для жюри

Нужны **Git, Node.js 22.12+ (рекомендуется 24 LTS) и npm**. Проверено на Windows с Node.js 24.19.0 и npm 11.19.1. Команды выполняются из корня репозитория.

```sh
git clone https://github.com/BAITC-Hacks/hack-97e25780-bears.git
cd hack-97e25780-bears
npm ci
```

Создайте локальный `.env` из примера (PowerShell):

```powershell
Copy-Item .env.example .env
```

Для macOS/Linux: `cp .env.example .env`. Для первого запуска оставьте ключи пустыми.

```sh
npm run dev
```

Откройте **http://localhost:3000**. UI и API работают на одном адресе; второй сервер или ручная настройка frontend API URL не нужны. Остановка — `Ctrl+C` в терминале.

Для запуска собранной версии:

```sh
npm run build
npm start
```

`npm start` требует готовую папку `dist`; установка должна включать devDependencies, поскольку launcher использует `tsx`. Не используйте `npm ci --omit=dev` для этой версии.

Только API (без интерфейса): `npm run start:api`. Не запускайте его одновременно с общим сервером на том же порту.

Проверка сервера в браузере: **http://localhost:3000/health**. В PowerShell:

```powershell
Invoke-RestMethod http://localhost:3000/health
```

Без ключей ожидаются `status: "ok"`, `storage: "memory"`, `aiConfigured: false` и оба `aiProviders` равные `false`.

## API-ключи и режимы AI

Все переменные задаются **на сервере**, в локальном `.env` рядом с `package.json` или в настройках окружения хостинга. После изменения перезапустите процесс.

| Переменная | Назначение | Значение по умолчанию / необходимость |
|---|---|---|
| `PORT` | Общий порт UI и API | `3000` |
| `CORS_ORIGIN` | Разрешённый origin при отдельных клиентах API | В примере `http://localhost:3000`; общий UI использует тот же origin |
| `GEMINI_API_KEY` | Уточняющие вопросы и формирование карточки в текущем UI | Необязательно; пустое значение включает fallback |
| `GEMINI_MODEL` | Модель Gemini | `gemini-flash-latest`, сохранена из backend участника |
| `GEMINI_TIMEOUT_MS` | Таймаут Gemini | `10000` |
| `OPENAI_API_KEY` | Отдельные endpoints уточнения `/api/clarifications` и `/api/tasks/:id/clarifications` | Необязательно; текущий UI эти endpoints не вызывает |
| `OPENAI_MODEL` | Модель отдельного OpenAI-сервиса | `gpt-4o-mini` |
| `OPENAI_TIMEOUT_MS` | Таймаут OpenAI | `10000` |

**Для настоящего AI в текущем конструкторе нужен собственный Gemini-ключ. Один только OpenAI-ключ не включает AI в этом интерфейсе.** Модель можно изменить в окружении на доступную вашему аккаунту. Наличие ключа в `/health` подтверждает настройку, но не успешную связь с провайдером, квоту или доступ к модели.

Без ключа, при таймауте или ошибке провайдера конструктор показывает резервный режим: задаёт вопросы по правилам и переносит введённые ответы в соответствующие поля. Неизвестные факты не дополняются. Это не реальный ответ AI. Каталог, рейтинг, отклики и выбор продолжают работать.

В Git хранится только `.env.example` с пустыми ключами. `.env` и его варианты исключены через `.gitignore`. Не добавляйте ключи в React, переменные `VITE_*`, README, screenshots или commits. Секреты из переписки использовать нельзя; опубликованный ранее ключ следует отозвать у провайдера.

**Реальный успешный запрос к Gemini/OpenAI при интеграционной проверке не выполнялся: проверка шла без ключей.** Поведение успеха, ошибки и таймаута AI-сервисов покрыто тестами с подставными клиентами.

## Как жюри проверить решение

1. Откройте приложение и переключитесь в **«Бизнес»**. Аккаунт не нужен: это общий демонстрационный переключатель ролей.
2. Нажмите **«Создать Карту + ИИ»**. С пустым описанием нажмите получение вопросов — появится ошибка, форма останется открыта.
3. Укажите компанию `Учебная столовая` и черновик: `Нужен сервис прогноза очередей в столовой кампуса для студентов и сотрудников.`
4. Нажмите **«Проверить полноту и задать вопросы»**. Без ключа убедитесь, что отображается подпись резервного режима.
5. Ответьте на шесть вопросов, например:
   - данные: обезличенный CSV посещаемости за четыре недели;
   - приёмка: прогноз пиковых часов проверяется на последней неделе данных;
   - ограничения: две недели, веб-прототип, без персональных данных;
   - связь: учебный куратор `demo@example.com`, два созвона в неделю;
   - пользователи: студенты выбирают время обеда;
   - результат: веб-прототип, исходный код и инструкция запуска.
6. Сформируйте карточку. Измените название, проверьте перенесённые ответы. Удалите и восстановите одно поле: рейтинг и детализация должны пересчитаться.
7. Нажмите **«Подтвердить и опубликовать»**. Карточка появится в каталоге. Перезагрузите страницу и найдите её по названию.
8. В режиме **«Студент»** нажмите **«Подать предложение»** у своей карточки. Заполните название команды, идею, план и срок. Ссылка на прототип необязательна; используйте только тестовые контакты.
9. После успешной отправки перезагрузите страницу. Отклик останется сохранённым; повторный отклик того же демо-студента на ту же карточку запрещён.
10. Переключитесь в **«Бизнес» → «Отклики студентов»**. Нажмите **«Выбрать команду»** или **«Отклонить»**. После обновления страницы решение должно сохраниться.

Данные при этом находятся в RAM одного запущенного сервера. Для демонстрации жюри может запустить приложение локально по этой инструкции; GitHub сам Node-сервер не запускает. Публичный адрес развёрнутого приложения в репозитории не заявлен. При размещении на хостинге ключ настраивает владелец сервера, посетителям вводить его в браузере не требуется.

## Проверки

```sh
npm run lint
npm test
npm run build
# Все три команды последовательно:
npm run check
```

`lint` здесь означает проверку TypeScript (`tsc --noEmit`), а не ESLint. Тесты используют встроенный Node test runner и Supertest.

При интеграции проверены типы, сборка, 29 backend-тестов и основной сценарий в браузере без ключей: пустой ввод, резервные вопросы, редактирование, публикация, поиск, отклик, выбор и сохранение после обновления. Реальный AI требует отдельной проверки с действующим ключом владельца.

## Структура и технологии

```text
README.md                  Общая инструкция
.env.example               Пустые серверные настройки
package.json / package-lock.json
server.ts                  Общий launcher: Express API + Vite / собранный UI

src/
  App.tsx, main.tsx         React 19 + TypeScript
  components/              Компоненты существующего дизайна
  api.ts                   Запросы UI к общему серверу
  types/, utils/, data/     UI-типы, формула рейтинга, демонстрационные профили
  backend-app.js            Express API (бывший app.js)
  server.js                Конфигурация провайдеров и отдельный запуск API
  routes/ui-router.js      Совместимость UI с общим хранилищем задач/откликов
  services/                Gemini и OpenAI, резервные режимы
  domain/                  Исходный backend-рейтинг
  storage/memory-store.js  Хранилище в памяти
  seed.js                  Стартовый пример серверной задачи
  *.test.js                Тесты API и сервисов
data/demo-seed.json        Продуктовые примеры для команды
docs/                     Контракт API, продуктовые материалы, сценарий демо
```

Frontend: React, TypeScript, Vite, Tailwind CSS, lucide-react. Backend: Node.js, Express, Google GenAI SDK, OpenAI SDK, dotenv. База данных не подключена.

Сохранена структура участников. `src/app.js` переименован в `src/backend-app.js`, поскольку на Windows его имя конфликтовало с `src/App.tsx` при проверке TypeScript. Общий launcher использует готовый backend вместо второго набора AI routes. API-адаптер сохраняет поля и формулу текущего UI; исходные `/api/tasks` и backend-формула сохранены для совместимости и отличаются от UI. Подробности и ограничения схем — в [контракте API](docs/api-contract.md).

## Границы текущей версии

- **Нет базы данных:** restart сервера сбрасывает карточки, отклики и решения до seed. Браузерное обновление данные не сбрасывает. Несколько серверных процессов имеют разные данные.
- **Нет авторизации и разграничения доступа:** все роли видят общие данные и могут принимать решения. Это хакатонная демонстрация, не сервис для хранения приватных задач.
- Изменения другой вкладки видны после обновления страницы; realtime-синхронизации нет.
- Черновик конструктора до публикации, закладки, профили и поиск/создание демо-команд не сохраняются на сервере. Кнопки уведомлений и аналитики не являются готовыми сервисами.
- AI-ранжирование команд, автоматическое назначение, чат, уведомления, полноценная аналитика, аккаунты, экспорт, история уточнений, второй язык, вложения и внешние интеграции в текущую поставку не входят.
- Закрытие отбора без победителя существует в исходном API; отдельного управления этим действием в UI нет. Решение по одному отклику в UI окончательное, отмены нет.
- Срок карточки по умолчанию — 14 дней из исходного frontend; произвольный срок из текста ограничения не разбирается автоматически в отдельный deadline. Рейтинг основан на длине заполненных полей, не на семантической оценке.
- Демонстрационные профили, команды и примеры не обозначают реальных заказчиков или партнёров. Кнопки заполнения демо добавляют явные учебные примеры, не результаты AI.

При нехватке времени приоритет имеет основной цикл. Дальнейшие улучшения: постоянное хранение, единая схема рейтинга после согласования командой, затем необязательные расширения из продуктового плана.
