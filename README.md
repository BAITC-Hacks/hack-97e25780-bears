# StartCard.ai — платформа практических бизнес-задач

StartCard.ai — демонстрационный веб-сервис, который помогает компаниям превращать черновики бизнес-задач в структурированные карточки, а студентам — находить подходящие задачи, собирать команды и отправлять предложения на их выполнение.

Приложение поддерживает два пользовательских режима:

- **Бизнес** создаёт задачу через пошаговый конструктор, получает уточняющие вопросы, редактируемую карточку и автоматический рейтинг её готовности.
- **Студент** просматривает каталог задач, использует поиск и фильтры, сохраняет карточки, формирует команду и отправляет отклик бизнесу.

## Основной сценарий решения

1. Представитель бизнеса вводит краткий черновик задачи.
2. Сервис формирует уточняющие вопросы о данных, критериях успеха, ограничениях и контакте куратора.
3. На основе ответов создаётся редактируемая карточка задачи.
4. Карточка получает рейтинг готовности от 0 до 100 баллов по семи критериям.
5. Бизнес публикует карточку в общем каталоге.
6. Студент изучает карточку и отправляет предложение команды.
7. Бизнес принимает или отклоняет поступившее предложение.

Gemini используется при наличии API-ключа. Без ключа основной демонстрационный сценарий остаётся доступен: сервер и интерфейс используют встроенные детерминированные шаблоны и эвристики.

## Архитектура

```text
Браузер
  └── React SPA
      ├── App.tsx — роли, навигация и состояние приложения
      ├── components/ — каталог, карточки, формы, модальные окна и кабинеты
      ├── data/initialData.ts — демонстрационные данные
      └── utils/scoreCalculator.ts — локальный расчёт рейтинга готовности
             │
             │ HTTP / JSON
             ▼
Express + TypeScript (server.ts)
  ├── POST /api/ai/clarify-task — уточняющие вопросы
  ├── POST /api/ai/build-card — формирование и оценка карточки
  ├── Google Gemini API — опциональная AI-генерация
  └── эвристический fallback — работа без внешнего API
```

В режиме разработки Express подключает Vite как middleware и обслуживает клиент с HMR. В production-режиме Express раздаёт статическую сборку из `dist/`.

Текущая версия является frontend/MVP-демонстрацией: карточки, команды, профили и отклики хранятся в состоянии React и возвращаются к исходным демо-данным после перезагрузки страницы. База данных и авторизация не подключены.

## Технологии

## Параметры окружения

Скопируйте шаблон:

```bash
cp .env.example .env
```

Доступные параметры:

| Параметр | Обязателен | Назначение |
|---|---:|---|
| `GEMINI_API_KEY` | Нет | Ключ Google Gemini для AI-генерации вопросов и карточек. Без ключа используется встроенный fallback. |
| `APP_URL` | Нет | Публичный URL приложения для окружения размещения. В локальном запуске можно указать `http://localhost:3000`. |
| `DISABLE_HMR` | Нет | Значение `true` отключает HMR и наблюдение за файлами Vite. |
| `NODE_ENV` | Нет для разработки | Установите `production`, чтобы сервер раздавал готовую сборку из `dist/`. |

Минимальный локальный `.env`:

```dotenv
APP_URL="http://localhost:3000"
```

Для проверки интеграции с Gemini:

```dotenv
GEMINI_API_KEY="ваш_ключ"
APP_URL="http://localhost:3000"
```

Не добавляйте файл `.env` и реальные секреты в Git.

## Запуск в режиме разработки

```bash
npm run dev
```

После запуска откройте [http://localhost:3000](http://localhost:3000). Сервер слушает `0.0.0.0:3000`.

## Production-сборка и запуск

```bash
npm run build
NODE_ENV=production npm start
```

Затем откройте [http://localhost:3000](http://localhost:3000).

Для предварительного просмотра только клиентской production-сборки можно использовать:

```bash
npm run preview
```

Vite выведет адрес preview-сервера в терминал. При таком запуске серверные маршруты `/api/ai/*` недоступны, поэтому для полной проверки рекомендуется `NODE_ENV=production npm start`.

## Команды проекта

| Команда | Назначение |
|---|---|
| `npm run dev` | Запуск Express и Vite в режиме разработки. |
| `npm run build` | Создание production-сборки в `dist/`. |
| `npm start` | Запуск TypeScript-сервера. Для готовой сборки используйте `NODE_ENV=production`. |
| `npm run preview` | Просмотр только Vite-сборки без Express API. |
| `npm run lint` | Статическая проверка TypeScript без генерации файлов. |
| `npm run clean` | Удаление каталога `dist` и файла `server.js`, если он существует. |

## Порядок проверки основного сценария

### 1. Проверка запуска

1. Выполните `npm install`.
2. Выполните `npm run lint`.
3. Выполните `npm run build`.
4. Запустите `npm run dev`.
5. Откройте `http://localhost:3000` и убедитесь, что отображается каталог StartCard.ai.

### 2. Сценарий бизнеса: создание карточки

1. Переключитесь в режим **«Бизнес»** в верхней части интерфейса.
2. Откройте конструктор новой задачи.
3. Выберите готовый пример или введите собственный черновик длиной не менее пяти символов.
4. Нажмите кнопку анализа черновика.
5. Ответьте на уточняющие вопросы; для быстрой проверки можно использовать демо-заполнение.
6. Сформируйте карточку и проверьте поля, рейтинг готовности и рекомендации.
7. Опубликуйте карточку и убедитесь, что она появилась в каталоге/кабинете бизнеса.

### 3. Сценарий студента: поиск и отклик

1. Переключитесь в режим **«Студент»**.
2. Проверьте поиск, фильтр категории, фильтр готовности и сортировку по рейтингу.
3. Откройте подробности любой карточки.
4. Сохраните карточку и убедитесь, что она доступна в разделе сохранённых.
5. Нажмите кнопку отклика, заполните предложение команды и отправьте его.
6. Убедитесь, что карточка появилась в разделе отправленных предложений.
7. Откройте раздел команд и проверьте создание команды или отправку заявки на вступление.

### 4. Проверка решения бизнесом

1. Вернитесь в режим **«Бизнес»**.
2. Откройте список поступивших предложений.
3. Примите или отклоните предложение и убедитесь, что его статус изменился.

### Ожидаемый результат

- интерфейс открывается без ошибок; 
- основной сценарий выполняется даже без `GEMINI_API_KEY`;
- новая карточка получает рейтинг и появляется в интерфейсе;
- поиск, фильтры, сохранение карточки, команды и отклики работают в рамках текущей сессии;
- `npm run lint` и `npm run build` завершаются успешно.

## Ограничения демонстрационной версии

- состояние не сохраняется после обновления страницы;
- данные пользователей, карточек и откликов являются демонстрационными;
- авторизация, база данных и постоянное файловое хранилище отсутствуют;
- порт сервера зафиксирован в коде как `3000`;
- качество AI-ответов при наличии ключа зависит от доступности внешнего Gemini API.
