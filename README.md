# Challenge Hub

> От краткой бизнес-задачи к понятному студенческому проекту и выбору команды.

**Статус:** разработка начата в отдельных ветках. Backend содержит API рекомендаций и модуль рейтинга; полный пользовательский цикл пока не собран. Выбран вариант C — Challenge Hub с AI-подбором и ранжированием команд. Планируемые функции ниже не следует считать готовыми без проверки.

### Для жюри: что решает продукт и как проверить текущую версию

Challenge Hub помогает бизнесу уточнить неполную постановку задачи, а студентам — понять ожидаемый результат перед откликом. Цель MVP — путь от черновика до публикации и ручного выбора исполнителей. Сейчас опубликованы отдельные части этого пути: демонстрационный конструктор и backend. Единого приложения, каталога и откликов пока нет.

#### Запуск frontend без API-ключа

Нужны Git, Python 3 с командой `python` и браузер. Выполняйте в новой папке; существующий рабочий каталог команды переключать не требуется.

```powershell
git clone --branch feature/member-3-frontend --single-branch https://github.com/BAITC-Hacks/hack-97e25780-bears.git challenge-hub-ui
cd challenge-hub-ui
git switch --detach 62ab2a2
python -m http.server 5173 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:5173`. Python используется только как статический сервер, а не как backend продукта. Команды приведены для воспроизведения и в рамках этой проверки README не запускались.

Проверка интерфейса:

1. Нажмите «Получить вопросы» с пустым полем: ожидается сообщение о необходимости ввода.
2. Введите «Нужно сократить очереди в студенческой столовой» и получите вопросы. В этой версии это фиксированный набор, без обращения к AI.
3. Заполните ответы и перейдите к карточке. Дополнительно заполните название, контекст или потребность и контакт, например `demo@example.com`.
4. Изменяйте поля: предварительный рейтинг и разбивка должны пересчитываться. Результат зависит от правил заполненности, а не от оценки моделью.
5. Подтвердите карточку. Известная проблема по исходникам: отключённые поля исключаются из `FormData`, и последующий пересчёт должен обнулить рейтинг. Требуется исправление и проверка в браузере.
6. Нажмите публикацию: сейчас она показывает только локальный статус. Каталог не создан, данные не сохраняются после перезагрузки.
7. Переключитесь в режим команды: отображается сообщение о будущем каталоге, а не список задач.
8. Для демонстрации ошибки откройте `http://127.0.0.1:5173/?questionsError=1`: первая попытка получения вопросов имитирует сбой, повторная использует фиксированный набор.

#### Отдельный запуск и проверка backend

Нужны Git, Node.js и npm. Конкретная проверенная версия Node.js пока не указана участником. В другом терминале и новой папке:

```powershell
git clone --branch feature/member-2-backend --single-branch https://github.com/BAITC-Hacks/hack-97e25780-bears.git challenge-hub-api
cd challenge-hub-api
git switch --detach 342d0ba
npm ci
npm start
```

В новом терминале PowerShell:

```powershell
Invoke-RestMethod http://localhost:3000/health
```

Ожидаемый результат — JSON со `status: "ok"`. AI-ключ для этой проверки не нужен. Для проверки валидации:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:3000/api/recommend-tasks -ContentType 'application/json' -Body '{"businessProblem":""}'
```

Ожидается HTTP 400. PowerShell покажет ошибку запроса — это ожидаемый результат данного отрицательного теста. Для непустого `businessProblem` без настроенного ключа ожидается HTTP 503. Для реального AI-запроса задайте собственный ключ в локальном `.env` по разделу 7 и перезапустите backend. Реальный вызов AI в этом отчёте не проверен.

Запуск обеих частей одновременно не соединяет их: frontend пока не вызывает backend. Приведённые проверки описывают отдельные компоненты, а не подтверждают готовность полного MVP.

## 1. Проблема

### Кто пользователь?

Представитель бизнеса, который размещает задачу и выбирает исполнителей, и студенческая команда, которая изучает задачи и откликается на них.

### С какой проблемой он сталкивается?

Бизнес описывает задачу слишком кратко, поэтому студентам трудно понять, что именно нужно сделать и какой результат ожидается.

### Как проблема решается сейчас?

Фактический текущий процесс пользователей не исследован. Гипотеза для проверки: недостающие сведения уточняются вручную в переписке или на встречах.

### Почему проблема важна?

Понятная постановка нужна командам для осознанного отклика, а бизнесу — для выбора исполнителей. Предполагаемая польза продукта — меньше неопределённости при согласовании задачи. Экономия времени и другие количественные эффекты пока не измерены.

## 2. Решение

### Наша идея одним предложением

> Для бизнеса и студенческих команд мы создаём Challenge Hub, который помогает уточнить задачу, опубликовать её и выбрать команду через отклики, с AI-подбором и ранжированием как следующим приоритетом.

### Что планируется реализовать?

1. Бизнес вводит черновик задачи и отвечает на уточняющие вопросы.
2. Система формирует карточку и показывает рейтинг готовности постановки.
3. После подтверждения бизнесом карточка публикуется в каталоге, команды отправляют отклики.
4. Бизнес выбирает команду. После готовности основного цикла планируется AI-подбор и ранжирование для помощи в выборе; окончательное решение остаётся за бизнесом.

### Основной сценарий MVP

**Вход:** краткое описание бизнес-задачи, ответы на уточняющие вопросы и отклики команд.

**Обработка:** уточнение постановки, расчёт рейтинга готовности, формирование и публикация карточки, сбор откликов.

**Результат:** понятная опубликованная задача и сохранённый выбор команды бизнесом.

Путь: черновик → вопросы → ответы → рейтинг готовности → подтверждение карточки → каталог → отклик → выбор команды.

Рейтинг готовности задачи и рейтинг соответствия команд — разные функции. Первый входит в основной сценарий; его формула и схема данных описаны в продуктовом контракте. Второй относится к AI-подбору и может быть исключён при нехватке времени; его критерии пока не утверждены.

При нехватке времени функция исключается, а ручной выбор по откликам сохраняется.

## 7. Установка и запуск

В текущей продуктовой ветке нет `package.json` и серверного кода, поэтому эти команды применимы только к отдельному checkout backend. Инструкция запуска общего приложения появится после интеграции.

- Node.js и npm; точная проверенная версия Node.js пока не зафиксирована командой.

### Установка

```bash
npm ci
```

### Переменные окружения

В backend-ветке есть `.env.example`. Скопируйте его в локальный `.env` и заполните ключ, если требуется проверить реальный AI-запрос. Не публикуйте `.env`.

| Переменная | Назначение | Обязательна |
|---|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI | Для AI-запроса; без ключа endpoint возвращает 503 |
| `OPENAI_MODEL` | Модель; по умолчанию в коде `gpt-4o-mini` | Нет |
| `PORT` | Порт сервера; по умолчанию 3000 | Нет |

> Не добавляйте реальные ключи, пароли и токены в GitHub.

### Запуск

```bash
npm start
```

Для разработки: `npm run dev`. Проверка здоровья: `GET http://localhost:3000/health`.

Реализованный endpoint `POST /api/recommend-tasks` принимает `businessProblem` (непустая строка), а также `audience`, `taskCount` и `context`. Пример JSON:

```json
{
  "businessProblem": "Нужно сократить время обработки обращений",
  "audience": "students",
  "taskCount": 3,
  "context": "Учебный пример без персональных данных"
}
```

Endpoint возвращает сгенерированные рекомендации заданий. Это ещё не API уточняющих вопросов и не AI-ранжирование команд.

Для тестов сервер должен запускаться с `NODE_ENV=test`, иначе импорт приложения также открывает слушающий порт. Тест отсутствующего ключа требует окружения без `OPENAI_API_KEY`, в том числе без ключа в `.env`. Пример команды PowerShell в таком тестовом окружении:

```powershell
$env:NODE_ENV = 'test'
npm test
```

Прохождение набора не подтверждено; известное несоответствие проверки `taskCount` указано в статусе выше.

## 8. Как проверить основной сценарий

План приёмки после реализации; это не отчёт о пройденных тестах. Адрес приложения и точные названия действий будут добавлены после рабочего запуска.

1. Ввести краткую бизнес-задачу и получить уточняющие вопросы.
2. Ответить на вопросы; проверить карточку и объяснение рейтинга готовности.
3. Подтвердить публикацию и найти карточку в каталоге.
4. Отправить отклик от команды и проверить его отображение для бизнеса.

# Единый кейс по геймификации практических заданий


### Рейтинг качества бизнес задач и открытый выбор команд

Команде необходимо создать работающий MVP, который помогает представителю бизнеса превратить первоначальное описание своей потребности или задачи в полноценную карточку, оценивает качество её заполнения и размещает задачу в открытом каталоге. Студенты самостоятельно выбирают интересные задачи и подают предложения, а представитель бизнеса принимает решение, с кем продолжить работу.

### Ключевой принцип
Главная геймификация направлена на бизнес: чем полнее и полезнее описана задача, тем выше её рейтинг и позиция в каталоге. Система может рекомендовать задачи студентам, но не назначает команды.

## Описание продукта
Платформа поддерживает два режима работы:

### 1. Режим для бизнеса
Представитель бизнеса описывает проблему, задачу или потребность. Система помогает:
- сформировать понятную и структурированную карточку задачи;
- оценить качество заполнения;
- выставить рейтинг и приоритет;
- разместить задачу в публичном каталоге.

### 2. Режим для студента
Студент просматривает открытые задачи, выбирает подходящие варианты и подаёт свои предложения. Система помогает:
- находить задачи по интересам и уровню подготовки;
- видеть рейтинг и описания задач;
- отправлять заявки или решения;
- участвовать в открытом competitive-процессе выбора команд.

## Основные сценарии
- Бизнес описывает задачу в простой форме;
- Система помогает привести её к единому формату;
- Задача попадает в каталог;
- Студенты просматривают и оценивают её;
- Представитель бизнеса выбирает наиболее подходящие команды или кандидатов.

## Техническое решение MVP
Проект реализует backend API для генерации рекомендаций по задачам на основе бизнес-контекста и целевой аудитории. Основной сервис:
- принимает описание бизнес-задачи;
- отправляет её в AI-модель;
- возвращает структурированный список рекомендованных практических заданий.

Начиная с этой версии проект фокусируется на backend-first MVP: API готов к интеграции с веб-интерфейсом и поддерживает два сценария использования — для бизнеса и для студентов.

# StartCard.ai — платформа практических бизнес-задач

StartCard.ai — демонстрационный веб-сервис, который помогает компаниям превращать черновики бизнес-задач в структурированные карточки, а студентам — находить подходящие задачи, собирать команды и отправлять предложения на их выполнение.

Приложение поддерживает два пользовательских режима:

- **Бизнес** создаёт задачу через пошаговый конструктор, получает уточняющие вопросы, редактируемую карточку и автоматический рейтинг её готовности.
- **Студент** просматривает каталог задач, использует поиск и фильтры, сохраняет карточки, формирует команду и отправляет отклик бизнесу.

## Основной сценарий решения

1. Представитель бизнеса вводит краткий черновик задачи.
2. Сервис формирует уточняющие вопросы о данных, критериях успеха, ограничениях и контакте куратора.
3. На основе ответов создаётся редактируемая карточка задачи.
4. Карточка получает рейтинг готовности от 0 до 100 баллов по семи критериям.
5. Бизнес публикует карточку в общем каталоге.
6. Студент изучает карточку и отправляет предложение команды.
7. Бизнес принимает или отклоняет поступившее предложение.

Gemini используется при наличии API-ключа. Без ключа основной демонстрационный сценарий остаётся доступен: сервер и интерфейс используют встроенные детерминированные шаблоны и эвристики.

## Архитектура

```text
Браузер
  └── React SPA
      ├── App.tsx — роли, навигация и состояние приложения
      ├── components/ — каталог, карточки, формы, модальные окна и кабинеты
      ├── data/initialData.ts — демонстрационные данные
      └── utils/scoreCalculator.ts — локальный расчёт рейтинга готовности
             │
             │ HTTP / JSON
             ▼
Express + TypeScript (server.ts)
  ├── POST /api/ai/clarify-task — уточняющие вопросы
  ├── POST /api/ai/build-card — формирование и оценка карточки
  ├── Google Gemini API — опциональная AI-генерация
  └── эвристический fallback — работа без внешнего API
```

В режиме разработки Express подключает Vite как middleware и обслуживает клиент с HMR. В production-режиме Express раздаёт статическую сборку из `dist/`.

Текущая версия является frontend/MVP-демонстрацией: карточки, команды, профили и отклики хранятся в состоянии React и возвращаются к исходным демо-данным после перезагрузки страницы. База данных и авторизация не подключены.

4. Сохраните карточку и убедитесь, что она доступна в разделе сохранённых.
5. Нажмите кнопку отклика, заполните предложение команды и отправьте его.
6. Убедитесь, что карточка появилась в разделе отправленных предложений.
7. Откройте раздел команд и проверьте создание команды или отправку заявки на вступление.

### 4. Проверка решения бизнесом

1. Вернитесь в режим **«Бизнес»**.
2. Откройте список поступивших предложений.
3. Примите или отклоните предложение и убедитесь, что его статус изменился.

### Ожидаемый результат

- интерфейс открывается без ошибок;
- основной сценарий выполняется даже без `GEMINI_API_KEY`;
- новая карточка получает рейтинг и появляется в интерфейсе;
- поиск, фильтры, сохранение карточки, команды и отклики работают в рамках текущей сессии;
- `npm run lint` и `npm run build` завершаются успешно.
