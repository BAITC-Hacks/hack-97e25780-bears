# Продуктовый контракт MVP

Этот документ фиксирует решения, общие для frontend и backend. Если реализация
расходится с ним, сначала согласуется изменение контракта.

## Пользователи и обязательный сценарий

- Представитель бизнеса создаёт задачу, редактирует карточку, публикует её и
  вручную рассматривает отклики.
- Студенческая команда видит весь каталог и подаёт один или несколько откликов.
- Переключение роли в демо выполняется без регистрации.

Сценарий считается реализованным только целиком:

1. Бизнес вводит короткий черновик.
2. Система задаёт не менее трёх уточняющих вопросов.
3. Ответы переносятся в редактируемую карточку без придуманных фактов.
4. Бизнес проверяет и подтверждает карточку.
5. Система показывает рейтинг 0–100, разбивку и советы по улучшению.
6. Подтверждённая карточка публикуется в общем каталоге.
7. Команда открывает карточку и подаёт отклик.
8. Бизнес принимает один, несколько или ни одного отклика.

## Единая схема данных

Все идентификаторы — строки. Даты передаются в ISO 8601. Пустое необязательное
текстовое поле хранится как пустая строка, а не выдуманный AI текст.

### TaskCard

| Поле | Тип | Назначение |
|---|---|---|
| `id` | string | Уникальный идентификатор |
| `title` | string | Название задачи |
| `industry` | string | Отрасль для отображения |
| `draftText` | string | Исходный текст бизнеса |
| `context` | string | Текущая ситуация и проблема |
| `need` | string | Что требуется изменить |
| `users` | string | Для кого создаётся решение |
| `data` | string | Доступные данные и материалы |
| `constraints` | string | Сроки, технологии и доступы |
| `expectedResult` | string | Конкретный результат работы |
| `successCriteria` | string | Измеримые критерии приёмки |
| `contact` | string | Email или телефон бизнеса |
| `interactionFormat` | string | Порядок консультаций и обратной связи |
| `status` | enum | `draft`, `confirmed`, `published`, `in_selection`, `closed` |
| `selectionOutcome` | enum | `pending`, `selected`, `no_selection` |
| `rating` | Rating | Текущая оценка готовности |
| `createdAt`, `updatedAt` | string | Даты создания и изменения |

### Rating

| Поле | Тип | Назначение |
|---|---|---|
| `score` | integer | Итог от 0 до 100 |
| `level` | enum | `draft`, `working`, `ready`, `priority` |
| `breakdown` | object | Баллы по семи категориям |
| `missing` | string[] | Названия пустых или слабых полей |
| `suggestions` | string[] | Конкретные способы повысить балл |

### Team

`id`, `name`, `interests[]`, `skills[]`, `technologies[]`.

### Proposal

| Поле | Тип | Назначение |
|---|---|---|
| `id`, `taskId`, `teamId` | string | Связи отклика |
| `solutionIdea` | string | Идея решения |
| `plan` | string | Краткий план работ |
| `duration` | string | Оценка срока |
| `prototypeUrl` | string | Ссылка; может быть пустой |
| `status` | enum | `submitted`, `accepted`, `rejected` |
| `createdAt` | string | Дата подачи |

Разрешено принять несколько откликов. Выбор одного не отклоняет остальные
автоматически. Действие «не выбирать никого» переводит все оставшиеся отклики
в `rejected`, задачу в `closed`, а `selectionOutcome` в `no_selection`.

## Публикация и статусы

Для публикации нужны `title`, хотя бы одно из полей `context` или `need`,
валидный `contact` и ручное подтверждение бизнеса. Остальные поля могут быть
пустыми: низкий рейтинг не скрывает задачу и не запрещает отклик.

- `draft` — карточка редактируется.
- `confirmed` — бизнес подтвердил содержание.
- `published` — карточка видна в каталоге и принимает отклики.
- `in_selection` — бизнес начал разбирать отклики; новые отклики ещё допустимы.
- `closed` — выбор завершён, новые отклики недоступны.

Каталог сортируется по `rating.score` по убыванию, а при равенстве — по
`updatedAt` от новых к старым.

## Формула рейтинга

Рейтинг детерминирован и пересчитывается после каждого подтверждённого
изменения. AI может предложить текст, но не выставляет балл.

| Категория | Поля | Максимум |
|---|---|---:|
| Контекст и потребность | `context` + `need`, по 10 | 20 |
| Данные и материалы | `data` | 20 |
| Ожидаемый результат | `expectedResult` | 15 |
| Критерии успеха | `successCriteria` | 15 |
| Ограничения | `constraints` | 10 |
| Пользователи | `users` | 10 |
| Связь с бизнесом | `contact` + `interactionFormat`, по 5 | 10 |

Для обычного текстового поля применяется коэффициент полноты:

- `0` — поле пустое после удаления пробелов;
- `0.5` — поле содержит от 1 до 39 символов;
- `1` — поле содержит 40 и более символов.

Особые правила:

- `successCriteria`: `0` для пустого значения, `0.5` для текста без числа,
  `1` при наличии хотя бы одного числа или процента;
- `contact`: `0` для пустого значения, `1` для валидного email или телефона,
  `0.5` для другого непустого текста.

Баллы поля равны `вес × коэффициент`. Итог — округлённая до ближайшего целого
сумма (значение `x.5` округляется вверх); результат ограничивается диапазоном
0–100. В разбивке допустимы половины
балла. Проверка длины — технически прозрачный критерий MVP, а не оценка
содержательной ценности текста.

Уровни готовности:

- 0–39 — `draft`;
- 40–69 — `working`;
- 70–89 — `ready`;
- 90–100 — `priority`.

`missing` включает пустые поля. `suggestions` содержит по одной конкретной
подсказке для каждого поля с коэффициентом меньше 1, начиная с категории с
наибольшим потерянным баллом.

## Контракт AI-функции

Вход:

```json
{
  "draftText": "string",
  "knownFields": { "context": "string", "need": "string" }
}
```

Выход:

```json
{
  "questions": [
    { "id": "string", "targetField": "data", "text": "string" }
  ]
}
```

Требования к выходу: от 3 до 7 вопросов, уникальные `id`, `targetField` только
из полей карточки, непустой `text`. Системная инструкция AI: определить
недостающие сведения и задать короткие вопросы; не добавлять факты и не
переписывать предположения как ответы пользователя.

Если API недоступен, ответ невалиден или превышен тайм-аут, используются
первые подходящие вопросы из fallback-набора:

1. Кто будет пользоваться результатом и в какой ситуации?
2. Какие данные или материалы доступны команде?
3. Какой конкретный результат вы ожидаете получить?
4. По каким измеримым признакам вы примете работу?
5. Какие есть сроки, технические ограничения и ограничения доступа?
6. Как команда сможет консультироваться с представителем бизнеса?

Интерфейс сообщает, что использован резервный режим, но не блокирует сценарий.
