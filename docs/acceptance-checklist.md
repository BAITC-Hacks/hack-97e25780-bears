# Критерии приёмки MVP

## Конструктор

- [ ] Бизнес может ввести свободный черновик.
- [ ] Система показывает минимум три уместных уточняющих вопроса.
- [ ] Ошибка или отсутствие AI API включает fallback и не обрывает сценарий.
- [ ] Ответы переносятся только в соответствующие поля без выдуманных фактов.
- [ ] Все поля карточки редактируются до ручного подтверждения.
- [ ] Нельзя опубликовать карточку без названия, контекста/потребности, контакта
      и подтверждения.

## Рейтинг

- [ ] Результат совпадает с формулой из `product-spec.md`.
- [ ] Показаны итог, уровень и семь категорий.
- [ ] Для слабых полей показаны конкретные подсказки.
- [ ] После подтверждённого изменения рейтинг пересчитывается.
- [ ] Граничные значения 39/40, 69/70 и 89/90 дают правильные уровни.

## Каталог и отклики

- [ ] Все опубликованные задачи видны независимо от рейтинга.
- [ ] Сортировка идёт по рейтингу, затем по дате обновления.
- [ ] Команда может отправить идею, план, срок и необязательную ссылку.
- [ ] Число откликов на задачу не ограничено.
- [ ] Бизнес может принять один или несколько откликов, отклонить отдельный
      отклик либо завершить выбор без победителя.
- [ ] Система никогда не принимает и не назначает команду автоматически.

## Демо и качество

- [ ] Эталонный сценарий проходит от черновика до ручного выбора команды.
- [ ] Переключение ролей работает без регистрации.
- [ ] Валидация и ошибки понятны пользователю.
- [ ] Нет секретов и API-ключей в репозитории или клиентском коде.
- [ ] Проект запускается по инструкции из README одной последовательностью команд.
- [ ] Показ занимает не более пяти минут.

## За пределами MVP

Регистрация и восстановление пароля, сложные роли, realtime-чат, уведомления,
календарь, файловое хранилище, рекомендации студентам, собственная ML-модель,
векторная база, мобильная адаптация, production-инфраструктура и полный
проектный трекер не являются условиями готовности.
