# Работа в команде

1. Перед изменениями проверьте `git status` и актуальность `main`. Сохраните свою незавершённую работу отдельно.
2. Создайте ветку под задачу. Укажите, какой пользовательский сценарий меняется.
3. Найдите нужную область по [архитектуре](docs/architecture.md). Не меняйте соседние функции без необходимости.
4. Выполните `npm ci`, затем `npm run check`. Изменения интерфейса проверьте в браузере.
5. Для профилей и уведомлений проверьте два разных профиля, адресата события, отметку прочтения и перезапуск сервера.
6. Обновите README и API-контракт, если поменялись запуск, поведение или поля запросов.
7. Выполните `git diff --check`, проверьте состав commit и откройте Pull Request с результатами проверки.

Используйте commits вида `feat: ...`, `fix: ...`, `docs: ...`, `test: ...`. Сохраняйте историю участников; не используйте force push для общей ветки.

В Git не должны попадать `.env`, ключи, `node_modules/`, `dist/` и `data/runtime/`. Для повторяемых проверок используйте тестовое хранилище, а не файл с профилями команды. Наличие тестов не означает, что они прошли: записывайте фактически выполненные команды и результаты.
